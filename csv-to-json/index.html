Technical specifications & limitations

Important format notes: All cell values are preserved strictly as strings to prevent unintended coercion of leading-zero identifiers (like postal codes, phone numbers, or account numbers).

Client-side privacy guarantee

Frequently asked questions

How does the parser handle empty or duplicate headers in CSV files?

If a column header is empty but contains row data, FormatFoundry assigns a unique deterministic name like "column_8" and displays a non-blocking warning. Unnamed trailing columns with no data in any row are pruned. Duplicate headers are renamed (e.g. "name_2") to ensure no data is overwritten.

Does this converter preserve leading zeros and identifiers?

Yes. All cell values are preserved strictly as strings. Identifiers like "00123", postal codes, and literal text are never silently coerced to numbers or other JavaScript types.

What happens if rows have uneven column counts?

FormatFoundry identifies uneven rows, safely pads missing trailing columns with empty strings so cell alignment is never shifted, and displays a warning listing the specific row numbers.
